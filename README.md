## 已确认的项目条件

- 场地尺寸为 1.2 m × 1.2 m，四周有约 10 cm 高围边。
- 方块约为 2 cm × 2 cm × 2 cm，单一纯色，与蓝黄场地颜色不同。
- 方块开局在中线附近等距排列，排列方向与中线平行。
- 我方小车开局位于对方半区，车头和推板朝向我方半区，可以直接推送。
- 机器人允许越过中线进入对方半区。
- 单场比赛少于 90 s，无人为干预；允许场外设备辅助及无线连接。
- 当前按底盘整体面积小于 150 cm²、最长边小于 40 cm 理解。
- 预算上限为 1000 元，设计目标尽量控制在约 500 元。

## 当前技术决策

- 硬件方案已确定：ESP32 + 520 带霍尔编码器减速电机 + AT8236 四路编码器电机驱动模块。按左右两台电机控制规划，沿用四轮底盘方向；MG310/TB6612 和开源整车方案转为历史参考。
- 控制分工：场外电脑负责视觉与规划，向 ESP32 发送运动指令；ESP32 负责车载控制、通信与失联停车，通过驱动模块控制电机。编码器读取及轮速 PID 在 ESP32 与驱动模块之间的具体分工，按模块教程和固件能力落实。
- 视觉：正式采用 1080p/30 fps 顶置 USB 摄像头与 Python + OpenCV；AprilTag 识别机器人位姿，方块采用“透视展开 → HSV 分割 → 形态学处理 → 轮廓/连通域 → 多帧确认”，第一版不使用神经网络。
- 机械：34～36 cm 宽、约 3 cm 高、离地约 1 mm 的可拆卸浅 U 形推板。
- 目标生成：按推板有效宽度构造“捕获走廊”，不再使用固定 20 cm 聚簇。
- 推块策略：`OPENING → MIDGAME → ENDGAME`；投递深度分为 `QUICK_CROSS`、`SAFE_DEPTH`、`DEEP_SECURE`。
- 安全：视觉位姿丢失超过 0.5 s 停车；无线中断超过 0.3 s 由 ESP32 自动停车；始终保留碰撞监控。
- 所有需要实测的阈值统一放入配置文件，便于模拟赛调参。
