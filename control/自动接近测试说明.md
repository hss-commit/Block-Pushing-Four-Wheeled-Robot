# 识别小车和方块后，自动给出方向并接近

这次新增的是一次单目标**自动接近**测试：图像 → 四红轮位姿与方块 → 稳定观测编号 → 既有 `StrategyRuntime → Planner` 选择目标组和接近点 → 左转/右转/前进/停止 → ESP32。接近点到达后停止，不执行推送和释放，不自动开始下一组。没有另写一套比赛选目标策略。

## 操作

**2026-11-03 手机热点入口：** 若电脑与ESP32都连接手机热点，请按 [手机热点联动说明](../测试用例/手机热点联动测试/README.md) 烧录STA版，先验证电脑可查询ESP32实际IP的 `/status`，再运行根目录 `启动手机热点自动接近测试.cmd` 并输入该IP。下面的标定、按键和运动限制继续适用。

**2026-11-03 蓝牙替代入口：** 若使用新蓝牙固件，请先按 [蓝牙测试说明](../测试用例/视觉蓝牙联动测试/README.md) 烧录和配对，运行根目录 `启动视觉蓝牙自动接近测试.cmd` 并输入蓝牙传出COM端口。下面的标定、按键、运动范围和限制同样适用；无需连接ESP32热点。原Wi-Fi入口继续可用。

1. **重新上传** `测试用例/视觉无线联动测试` 工程到 ESP32。本次增加 `/step` 方向接口，旧的仅直行固件不能运行新测试，程序会检测版本能力并提示。
2. 电脑连接热点 **ESP32-Vision-Test**，密码 **esp32car123**。手机继续经 USB DroidCam 提供画面。
3. 先架空核对电机方向：前进沿用四路 `0.1`；左转 A/C 为 `-0.1`、B/D 为 `0.1`，右转相反，即预期原地差速转向。实际通道、安装方向未实车确认，不能把视觉朝向正确当作电机映射正确。
4. 双击根目录 **启动视觉自动接近测试.cmd**。N/P 选摄像头；Enter 按左上、右上、右下、左下选四个**真实场地内角**，再 Enter 确认。手机与场地保持固定，四轮、所有方块及全场都要入镜。程序把黄色区旋转到画面下方，显示方向可能与原相机画面不同，这是为了与共享策略坐标一致。
5. 点击**一个方块的中心取色**，不要点轮胎或标注。程序识别同色方块并自动给出接近点（紫圈）、到接近点的青色线，以及 `NEXT: LEFT / RIGHT / FORWARD / STOP`。取色改变时会先停车并重建观测。
6. 场地、小车和方块观测有效，目标和车姿稳定约 0.5 秒后显示 **READY**。按一次**空格**开始，后续每个短动作后根据新画面修正，不需要逐步按方向键。**X** 停止，**R** 重新准备，**S** 保存，**Esc** 退出。
7. 到达接近点（估计位置误差 ≤25mm）后显示 `APPROACH REACHED / NO PUSH` 并停止；需要按 R 才能重新准备。架空确认左右方向与停止可靠后，再用空旷无人的单车场地进行低速落地接近测试。

只显示指令、完全不连接小车：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\control\vision_approach_test.py --dry-run
```

可用 `--camera 1` 和 `--host http://192.168.4.1` 改摄像头/地址。如果实测只有左右转向完全相反，可用 `--invert-turns` 交换转向；这不能修正其他电机接线或底盘映射问题。不要凭猜测启用。

## 本版控制范围

- 复用 `strategy/config.json` 的 1200mm 方形场地和阶段策略。黄色目标区映射到策略 `lower`；这只是当前试验约定，不是正式比赛规则已确认。中线须近似均分场地，校正后与画面轴向一致，否则停止。
- 动作由目标接近点与当前车头的夹角决定：误差超过约 12°先转向，否则前进。每次 `/step` 运行约 120ms 后车端主动发送停止；电脑至少间隔 220ms 才能发下一步，方向变化时先停止旧动作。旧 `/pulse` 单次250ms测试仍可使用。
- 接近点、目标 ID 在任务期间锁定。方块只做静止阶段的近邻匹配，匹配歧义、明显粘连（检测框边长大于约40mm）、目标消失或移动超过15mm即停。这不是已能处理推送、遮挡恢复和多车比赛的完整跟踪。
- 以轮胎/车体可见外包络的圆形半径再加20mm估算完整占地，保守检查场地边界与**所有已检出方块**。接近间隙按可见占地增加，不盲用原有车体尺寸。目标点与直线路段都须有余量；直线被挡会显示 `STRAIGHT ROUTE BLOCKED` 并停止，暂不尝试绕路。
- 运动时失去车头、目标、中线，数据处理过期、通信失效、车姿突变、4秒无视觉进展或20秒总测试时间到达都会停止，并要求重新准备。到达依据新的视觉位置，不以等待时间冒充完成；完成计数仍是0，不伪造推块成功。
- 场地四角标定不等于已完成相机畸变、轮胎高度、推板前伸、轮速和机械制动标定。120ms动作的真实位移与停止距离尚未实测。当前路径检查只能处理检测到的同色块和边界，不能发现手、线缆、其他颜色障碍物或对手车；测试区域须人工确认清空。冻结或缓冲的相机画面可能无法可靠识别。

## 排查与记录

- `NEED ROBOT HEADING`：四轮未识别完整，或前后轮距差不足；先回到原视觉定位入口核对。
- `FIELD / YELLOW DIRECTION INVALID`：四角、中线或蓝黄方向不可靠；退出后重新校正。
- `NO STRATEGY APPROACH GOAL`：共享策略没找到适合的任务；可先用单个蓝区/中线附近方块，留出车后接近空间。
- `FOOTPRINT / STRATEGY STOP`：估计车体过于靠墙/靠块，或策略保护停止。
- `STRAIGHT ROUTE BLOCKED`：目标接近点的直线通道不够宽；本版不会硬穿过去。
- `MERGED / OVERSIZE BLOCK`：取色把轮胎、场外物体或粘连多块合并识别；检查标定、取色和方块摆放。
- `STALE VISION / WIFI`：处理超过0.2秒或通信反馈超过0.3秒；检查画面和网络后按R重新准备。

运行日志位于 `vision/results/approach-时间/events.jsonl`。S 保存原始帧、旋转校正后的标注帧、机器人/方块/决策和四角参数，便于复查。固件回执仅说明接收请求，不代表电机执行成功。
