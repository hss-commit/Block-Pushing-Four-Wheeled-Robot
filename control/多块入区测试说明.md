# 多块实车入区测试（菜单6）

> 当前菜单：6为单块，8为连续多块。下文较早的菜单6多块说明是历史记录，以本段和启动菜单为准。

最新目标锁定修正（2026-11-20）：选中一块后，丢码、丢目标、短时网络状态等待以及路径重新规划都不能改选另一块。车码丢失先停车，恢复后继续原任务；目标换编号只允许位置唯一接续。退车后看不到原块时停车等待其实际核验，取消此前“0.8秒后放弃并选下一块”。只有当前块实际留在黄区并完成核验才解除锁定；R重新准备可人工清锁。若当前块不可恢复，窗口保持停车和原目标，不假装完成。无需本轮重新烧录，须重开电脑端加载。

当前接触推送方案（2026-11-20，替代下文丢框即短退）：实际观察到目标在推板附近后，若丢框，按新鲜车码位置继续低速直推；画面显示 `CONTACT PUSH / CAR POSITION / BLOCK UNOBSERVED`，日志 `block_estimated=true` 及 `estimated_block_mm` 明确表示估计，不是识别结果。推板前沿越过实测分界并留出“方块半宽+20mm”后退开核验，或连续遮挡推进200mm/20秒后退开重看。偏航约8°、横漂15mm、4秒无车位姿进展、前方障碍或定位失效会停车重新观察。退开后实际看到方块完整在黄区0.5秒才增加VERIFIED，单块6同样不能凭估计计数。车体/贴码偏移应按实物核验，软件投影不等于地面精确测量。只改电脑端，重开6/8，无需本轮重烧。

2026-11-20 接触遮挡修正（6和8）：保留车体尺寸，对已锁定目标开放车头前约两倍块边长的接触带（不超过车体投影长度40%），只接续位置、大小和唯一近邻符合的真实检测。侧轮和车尾仍过滤，不会用历史位置补画虚拟方块。推板接触后完全看不到目标，且车码/场地/画面有效、后方退路可用时，使用低速细步短退约30mm重识别，最长1.2秒；观察到目标恢复后继续。未恢复则停车重选，不继续盲推、不增加成功数。重开电脑端生效，不需要本轮重新烧录。

2026-11-20 菜单8转弯优化：以动作结束后新采集的有效车头角度判断是否起转。连续两步转角不足1°，且20°转向扫掠范围内无已识别障碍/边界冲突时，下一步使用现有±0.1、120ms正常力度，实际转动后恢复细调；小于15°的偏角同样支持起转补偿。旧固件不支持中/细转向档时，偏角≥25°直接使用经空间检查的正常短动作，避免反复发±0.025却不动。新固件继续按15°分界选择±0.05的60/35ms中/细档。指令值不是实测物理速度，需现场核对转角；每步仍停车并等待新画面。发加力指令不再重置4秒无进展计时。本轮只更新电脑端，重开测试8生效，无须重新烧录。

2026-11-20 菜单8交接：看到方块中心进入黄区达到“方块半宽+5mm”后退开推板，不再必须深推30mm才退。退车时颜色漏检不会立即丢弃任务；唯一40mm内的新编号可接续原块。按沿退车方向的实际位移判断退够，越过预定终点也可结束。退开后看到方块完整留黄区0.5秒才计数；仍看不到则停车观察0.8秒，不计数并继续选蓝区下一块。已在黄区的块不选，后来回蓝则可重新选择。无需重新烧录，重开电脑端测试8加载。软件验证不等于实车验收。

目标：逐个把可见方块推入黄色区域，退开核验后自动寻找下一个。此为首版实车联调入口，软件模拟通过不等于实车已验收。

## 开始

1. 重新上传 **测试用例/手机热点联动测试** 的最新固件。本轮新增80ms低速细动作，菜单6会检查 `gentle_step_ms:80`，拒绝旧版。键盘遥控和原视觉功能仍兼容此固件。
2. 电脑和ESP32连接同一热点，退出遥控及其他摄像头窗口，保持DroidCam连接。双击 **启动机器人.cmd**，S核对实际IP和摄像头。
3. 先用 **2** 确认定位码、车头、车体框及方块识别。已保存车宽200mm、沿车头长100mm（含推板）、黑码50mm，不必重复填写。贴码偏移若不居中仍需按实际核对。
4. 首轮只放 **2～3个分离的同色方块**，在蓝区/中线附近，方块之间建议至少约30cm，远离场地边缘，移走其他物品和车辆。暂不从挤成一堆、互相接触的方块开始。
5. 选择 **6：多块入区测试**。Enter选四个真实场地内角，确认蓝黄分界被识别；点击一个方块中心取色，检查其他方块也各自被识别。画面校正后黄色区在下方。
6. 场景稳定后按一次 **空格**启动。与菜单1不同，此模式取色后不会自动运动。**X**停止锁定，**Esc**停车退出，**S**保存现场，**R**重新准备（须重新按空格）。

## 执行过程

共享比赛策略选一个目标 → 检查接近路径及推送走廊 → 绕到目标后方 → 对准黄色区 → 直线推入黄色区 → 按视觉位移倒退留出转向空间 → 停车持续观察约0.5秒，确认方块仍在黄区 → 增加VERIFIED计数 → 选下一块。

本模式使用实测车体外廓推算占地，单任务只捕获一个方块；共享策略在本测试中以黄色中线内约60mm为通常入区目标，计数还要求退开后目标完整留在黄区。全部当前观测方块已入区时DONE停车。起初就在黄区的方块不会冒充新完成数量。90秒策略计时及赛末停车沿用共享策略；这不表示正式比赛得分或完整比赛系统已验收。

低速细动作每次80ms：前进/后退指令±0.04，左右原地转向两侧±0.025。它们是驱动板指令值，不是已测物理速度。本模式不套用键盘长按加速，依靠新画面反复校正。

## 会停止的情况

- 任一方块丢失、突然新增、编号匹配不唯一、粘连框过大，或非目标块意外移动。
- 定位码、车头、车体尺寸或场地标定失效；位置突变；贴近场地边缘。
- 接近路径、推送走廊或退车通道不够宽；原地转向占地也必须留出余量。
- 目标偏离推送线、车头漂移、方块位移与车辆接触不符、4秒无视觉进展。
- 网络/图像过期、通信错误、策略赛末停车或需要重新规划的阶段变化。

2026-11-10现场修正：模式6等待HTTP回执上限改为600ms，车端每步动作仍为80ms独立限时，不重试动作。此上限只适用于模式6，旧视觉模式默认仍为180ms。状态查询移到取新画面之前，避免查询等待把旧画面拖过期；视觉处理时限仍为0.2秒、决策时链路新鲜度仍为0.3秒。允许两次回执等待及处理带来的最长1.5秒观测间隔，间隔期间车端80ms动作已到期，下一步仍须基于新采集的有效画面；不允许重复旧帧续行。准备阶段偶发慢帧会重新等待稳定，运行中实际画面/链路过期仍停车锁定。超过600ms或其他错误仍会停止，不能保证热点完全无抖动。只更新电脑程序，无需再次烧录。

只对识别出的同色块和场地做路径检查，不识别所有障碍物、手或未贴码对手。码在车顶、方块在地面存在高度/透视误差；若车体框压住实际目标而被过滤，程序会停止，不预测被遮挡块继续推。无路径时停车，不强行穿过其他块；最初的分散布置是本轮测试条件。

## 记录与软件验证

日志：`vision/results/multi-push-时间/events.jsonl`。记录目标、阶段、请求/回执、VERIFIED数量及异常；S保存原图、标注图和场地四角。

`control/test_multi_push_control.py` 覆盖两块连续入区、接近绕路、转向、推送、退车核验、稳定编号及丢块/过期/外力移块/场地失效/卡住停车。`control/test_multi_push_integration.py` 使用实际ArUco/方块图像、完整应用循环及本机HTTP，走通两块入区并最终停车，不连接真实小车。已纳入 `运行软件检查.cmd`。

## 原窗口重连与启动反馈

通信异常后保持原窗口、相机及场地标定，保留最后画面并锁定停车。网络恢复后按R明确重连，失败继续留在原窗口；成功保留取色和已确认完成数量，重新观察并规划，必须重新按空格才运动。相机断开或分辨率改变仍需重新标定。Esc或手动关窗才退出。此功能只在加载新版源码的进程中生效，不能热替换已经运行的旧进程。

PREPARE表示正在等待稳定，READY才允许空格启动。MERGED/OVERSIZE表示粘连或框过大，AMBIGUOUS表示方块无法唯一匹配；先分开方块、检查轮子误识别，再按R重新准备。按空格被拒绝时控制台和日志会记录原因，不能用空格绕过这些检查。

## 一次空格提交启动请求

模式6按一次空格会记住启动请求，显示START REQUESTED；只在网络、标定、定位及方块识别持续有效后开始，无需反复按空格。未取色或未稳定会显示等待原因，不能跳过检查直接动车。X取消并停车，R取消并重新准备。运动中再次按空格不重复启动。

停车准备中状态包偶发超时会保持画面、每1秒自动重查；粘连/匹配歧义也先等待识别恢复。运动中的通信或识别错误仍锁定停车并取消启动请求。网络故障页：R只重连，空格明确请求重连并在条件有效后开始，X取消/保持停车。以上只在新加载源码的进程中生效，不会热替换当前旧进程。
