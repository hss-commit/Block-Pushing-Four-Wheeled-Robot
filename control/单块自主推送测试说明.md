# 单块自主直线推送：视觉触发一次，推移约10厘米后停

这是现有单次短动作之后的一次单块功能试验：只放一个清晰分离的方块，初始车头大致对准它，场景稳定倒计时3秒后自动前进，持续根据小车和方块位置发120ms短动作，方块沿初始车头方向移动约100mm后停车。不会自动开始第二次，不使用左右转向，也不绕路。不是完整比赛自主推块。

用户已反馈原250ms短动作测试成功。旧程序多次空格只动一次，是要求R重新准备的单次触发设计；本入口不需要按空格启动或逐步按方向。

## 开始前

- 保持当前 **手机热点联动测试** 固件，无须再次烧录ESP32。电脑和ESP32连接同一个 `Robot-Test` 热点，手机仍经USB DroidCam传画面。上次ESP32地址是 `10.112.135.116`，重连后可能改变。
- 先关闭旧的实车测试、只看画面窗口及其他占用DroidCam摄像头的程序；DroidCam客户端本身保留。当前手机摄像头编号为1，新入口默认使用1，可用N/P切换。
- 固定手机，完整拍到 **1.2m × 1.2m场地内沿、全部四轮和唯一方块**。场地中央留出空旷通道，车头大致对准方块，方块位于车头可见外包络前方0～200mm。转向还未实车验证，本版只前进。
- 不要求填写推板尺寸；程序以可见轮胎外包络估计车前缘和占地。真实车头/推板前伸、镜头畸变和高度尚未校准，估计并不等于真实占地。首次在中央空旷处观察，手保持离开运动区域。

## 操作

1. 双击根目录 **启动单块自主推送测试.cmd**，输入ESP32实际IP。
2. 预览显示手机画面后，按Enter进入选四角，按左上、右上、右下、左下点击真实场地内角，再Enter确认。蓝黄分界应完整可见；尺寸按项目已确认的1200mm换算。
3. **点击唯一方块的中心取色。** 识别必须只剩一个方块，四轮和车头必须有效。初始侧向偏差须不大于20mm、朝向偏差须不大于8°；否则停在 `ALIGN CAR WITH BLOCK` 提示，调整初始摆放后再等待。移动场地或手机需退出重新标定。
4. **一旦满足条件，就会显示COUNTDOWN并自动倒计时3秒开始，不需按空格。** 取色前就应摆好车与方块、清空通道。倒计时期间场景不稳定会重算，按X可取消并锁定停车。
5. 运动时显示方块位移 `BLOCK: .../100 mm`，按新画面分步前进；到位显示DONE并停车。判断依据是新观测到的方块位移，不是固定等几秒，也不是只看车辆移动。
6. **X** 停车并锁定；**Esc** 停车退出；**S** 保存原始/校正图片和数据；**R** 开始下一轮准备与自动倒计时。完成后或故障停止后不自动恢复，只有明确按R或重新取色才会准备下一次。不要按着R不放。

先只看识别和自动决策、不连接车辆：

```powershell
.\.venv\Scripts\python.exe -X utf8 control/vision_approach_test.py --single-push --camera 1 --dry-run
```

直接运行实车入口（无需交互输入IP）：

```powershell
.\.venv\Scripts\python.exe -X utf8 control/vision_approach_test.py --single-push --camera 1 --host http://10.112.135.116
```

`--push-distance` 可将目标改为20～150mm，默认100mm。位移为当前平面标定的估计值，到位后还存在实际惯性/制动距离，需用实物测量核对，尚未做真实自主推送验收。

## 停车条件及边界

**运行异常反馈（2026-11-03）：** 通信超时、摄像头断开/分辨率改变或图像处理异常时，程序先锁定停车并尝试发送停止请求，随后保留STOPPED错误窗口，直到按Esc或手动关闭。错误类型、原始原因写入本次 `events.jsonl` 的 `error` 事件；停止未确认则另写 `stop_unconfirmed`。退出错误画面后测试以非零状态结束，需排除原因并重开程序；不会在网络恢复后自动运动。普通Esc和关闭窗口也会记录退出原因。安全时限没有放宽。

- 小车或方块丢失、同色块不止一个、粘连/检测框过大、位置跳变、车头或横向偏离、前方空间不足、接近场地边缘，都会停止或不启动。
- 运动时图像处理超过0.2s、通信反馈超过0.3s，或观测间断超过0.35s即停；倒计时期间观测间断则重新准备。摄像头驱动提供缓冲旧画面或冻结图像时，获取时间戳不能保证真实画面新鲜。
- 3秒没有视觉进展、接触附近2秒未见方块移动、车体超过观测允许路程、运动20秒仍未完成，都会停止并锁定。方块移动与车体前进明显不符，不计作推送完成。
- 只处理取色识别出的方块和车，不检测所有颜色障碍物、手或其他车辆。须人工确认通道空旷；目标被车头遮挡或进入轮胎外包络导致检测丢失时也会停止，不凭空猜测其位置。
- 车端仍用已有120ms动作限时和零速指令；电脑崩溃/相机断开不会把一条动作延长为持续行驶。该机制没有驱动板/编码器回读，不能保证驱动板已实际执行零速，物理异常应关闭驱动板。
- 本次只验证向初始车头方向推约10厘米。不会退车释放，不把视觉到位冒充比赛完成计数；多块选择和比赛策略另行接入。

日志在 `vision/results/single-push-时间/events.jsonl`，记录状态、请求、回执及发送时的视觉进度，S另存现场图片和四角信息。

## 软件检查

`control/test_single_push_control.py` 覆盖自动倒计时、接近/推送、真实方块位移到位、不自动重复、识别/链路过期、位置跳变、偏离、边界、无进展及“外物移动方块不能冒充推送”。另外用真实OpenCV合成画面、完整应用循环和模拟车辆回执走通从取色到自动前进、视觉到位、停车，全程没有空格输入，不连接真车。

软件检查不能代替现场接近、接触、打滑、遮挡和制动验证。2026-11-03新增代码的真实自主推块测试仍待进行；原有人工短动作成功是用户反馈。
