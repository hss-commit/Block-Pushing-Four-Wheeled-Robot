# 策略代码到实物的复用边界

目标：模拟调试和真实比赛始终使用同一份前中后期策略核心，修改目标选择和投递策略时只改共享代码。

按已定架构，策略部署在场外电脑上。ESP32 执行运动指令、读取车载反馈并处理车端失联停车，不需要将 Python 策略翻译成 ESP32 固件。

## 当前可复用的代码

| 文件/功能 | 真实比赛使用方式 | 当前验证 |
|---|---|---|
| `planner.py` | 原样导入：阶段切换、目标选择、回收/保护、投递深度、锁定和停止决策 | 纯 Python 标准库；无需 OpenCV 窗口即可运行 |
| `revise_task_for_endgame()` | 执行器在进入终盘时调用，重新规划尚未接近的任务、缩短推送或提前释放 | 已由模拟器调用，有独立检查 |
| `runtime.py` | 接收带真实时间戳的视觉观测和车载反馈，构造同一份策略输入 | 模拟器也从这个入口进入；时间戳、缺数据与失联检查已覆盖 |
| `config.json` | 保留参数结构，替换为正式规则和实物测量值 | 目前为演示/预估参数 |
| `simulator.py` | 用于开发测试 | 合成传感器、简化接触和圆形车体路线均不作为实车控制实现 |

## 实际数据链路

```text
顶置摄像头 → OpenCV 标定、机器人定位、方块跟踪
                              ↓ Observation
ESP32 心跳/故障反馈 → Feedback → StrategyRuntime → Planner
                                                    ↓ Decision
                           实车路径检查与动作执行器 → 速度指令 → ESP32
```

`StrategyRuntime` 是真实数据接入的入口，尚不是能够直接连上摄像头或发送无线指令的完整程序。真实视觉生产者、通信接收和实车执行器仍需实现。

## 接入契约

创建一场比赛实例：`StrategyRuntime(config, started_at_s=time.monotonic())`。每次调用 `decide(observation, feedback, now_s=time.monotonic())`，下一场创建新实例。

- 坐标统一为场地毫米坐标，原点左下；车头角度为弧度，从 +x 起逆时针为正。机器人位置必须对应车身中心，不能直接拿偏置的顶部标记中心代替。
- `Observation.pose_seen_at_s` 和 `blocks_seen_at_s` 保存获得有效观测的帧采集时间。上一次位置被保留、处理延迟或再次调用策略，都不能刷新这个时间。
- `Feedback.received_at_s` 是电脑收到有效心跳的本机时间。所有时间属于电脑的同一个单调时钟；不能直接混入 ESP32 的启动计时或墙上时钟。
- 缺少位姿填 `robot=None`，缺少有效观测时间填 `None`；接入层将输出 STOP。经过有效检测确认没有方块可以传空元组；检测失败不能冒充空场地。
- 方块 ID 必须由真实多帧跟踪维持。现有照片工具的区域编号仅针对单张图，不能直接用来判断“同一方块被对手推回”。
- `collision_risk` 是必填状态，由场地/路径安全检查提供。实车不能照抄模拟器的固定 `False`。`opponent=None` 只表示未提供对手观测，不等于已证明无障碍。
- `completed_pushes` 只在实车确认完成推送及释放后累加。模拟器使用模拟状态计数，实车应使用执行状态与视觉反馈，不能照搬一个固定等待时间。

## 输出如何执行

`Decision` 给出目标方块、接近点、推送终点和朝向。端点是机器人中心坐标，已考虑推板前伸及方块半宽。它不是 PWM、轮速或可以直接发送给电机驱动板的数据包。

- `STOP`：中断任何当前任务，控制层持续发零速度；ESP32 自身也必须有失联看门狗。
- `WAIT`：当前没有新的可选目标，空闲执行器保持零速度。若任务已在推送或释放，不能把重新选目标的 WAIT 当成该任务自动完成，也不能盲目保留上一条速度。执行器应根据当前任务、最新观测和安全检查决定继续或中止。
- `CAPTURE/RECAPTURE/SECURE`：空闲执行器先检查包含推板的完整路径和时间预算，通过后才接受任务。执行中保持任务状态，避免每帧重新启动接近。
- 阶段进入 ENDGAME 时，执行器调用同一份 `revise_task_for_endgame()`；接收到 STOP 时优先停止。

运行层和实车执行器之间还需要持续的任务进度反馈。此说明没有把模拟执行器包装成已可用于电机控制的代码。

## 到货后的验证顺序

1. 顶置视觉输出机器人位姿和稳定方块 ID，核对坐标、朝向、标记偏置及观测延迟。
2. 实车架空/低速完成通信、轮速及断联停车测试。
3. 实车执行单个接近、对准、短推和释放动作，测量速度、转向、制动距离、漏块和耗时。
4. 将这些测量值写入配置，在实车接入相同的 `StrategyRuntime` 与 `Planner`。
5. 完整比赛测试中继续改共享策略和配置，模拟与实车不维护两套前中后期逻辑。

已验证的是软件复用边界和模拟/接口一致性；硬件未到，尚不能承诺实际推块效果、定位精度或完整控制闭环已通过。
