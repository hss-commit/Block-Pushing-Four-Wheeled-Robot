# 图片识别后的推送候选排序

当前目标保留黄色。程序新增 P1/P2/P3 场景优先级，供观察和调试，不发送电机指令。该模块位于 `strategy/scene_priority.py`，与 `Planner` 共用 `capture_centers()` 候选走廊中心计算；不是另一套实车比赛执行策略。

## 怎样排序

1. 只处理检出的蓝区、压线候选区域；黄区默认保留。分界线或场地范围无效时不排名。
2. 沿蓝黄界线建立横向轴、朝黄色建立推送轴。按现有 `strategy/config.json` 的推板有效宽度生成同通道候选组，同时比较不同深度的子组，避免把远块强行绑定给近块。
3. 评分为区域收益 /（背后接近预留长度 + 推送长度 + 退出预留长度），各长度用场地投影跨度归一化，不是秒数。没有小车位姿，不计算实际接近、转向或绕障耗时。
4. 面积超过全图区域面积中位数 2.2 倍时，启发式标为疑似粘连；该区域只计 0.65 单位收益，真实块数为未知，不能按六块或按面积整数倍计分。受透视、反光和样本分布影响，该判据可能漏报/误报。
5. 按当前参数缺侧边/背后余量的组，评分再乘 0.4，并排在未触发这些风险的组后，标记需检查几何条件。它们仍可能显示 P 编号，P 不等于可执行许可。直推走廊会碰到已检出的黄区方块时排除该候选。
6. 依分数选显示组，已分配区域不重复；不能组成剩余候选的区域显示 REVIEW/暂缓并给原因。每次推送后必须重新识别和重算，不把整张排名当作固定动作序列。

推板等参数目前仍为原策略演示值，例如 350 mm 宽、1200 mm 场地，尚未实测确认。JSON 保存本次使用的几何参数及 `executable: false`、`requires_path_check: true`。完整车体和推板转弯扫掠、侧向漏块、打滑、对手和未知障碍不在此预览内。

## 已校正与未校正画面

四角校正后的实时/照片模式会标记 CALIBRATED；这只表示使用了用户选角，不表示毫米误差已验收。原图批量模式和本次六图保存结果未透视校正，距离、走廊宽度和围墙余量只按图像投影估算，标记 UNCALIBRATED。图片没有覆盖全场时，裁切边界尤其不能当作真实围墙。

排名只覆盖检出的区域，原识别中的漏检、粘连继续存在。场地优先级不等于小车最优顺序；加入车的位置、朝向、稳定 ID 和真实路径检查后，应交给同一 `Planner` / 动作执行器重新决策。

## 使用

- 原照片与摄像头入口无需新参数，取色后自动显示优先级；S 同时保存 `priority.md` 与含评分理由的 JSON。
- `--batch` 同样生成优先级和 `priority-summary.md`。
- 原图移动后，可对已保存批量识别结果重新排序，不重新分割已画框的图片：

```powershell
.\.venv\Scripts\python.exe .\vision\photo_vision.py --rank-results .\vision\results\2026-10-20-priority-photos --output .\vision\results\2026-10-20-scene-priority
```

结果：[六图排序总览](../vision/results/2026-10-20-scene-priority/overview.png)、[逐图中文理由](../vision/results/2026-10-20-scene-priority/priority-summary.md)。每张有 `ranked.png`、`priority.md` 和 `result.json`。输入检测结果保留，输出需独立目录；结果目录依然只在本机保存。

## 已验证

新增 7 项场景排序检查：近组与远块取舍、走廊宽度、墙边降级、黄区块阻挡、粘连不虚构块数、无效观测清除旧排名、图像旋转保持排名。原策略/运行层/模拟器检查与它们合计 33 项通过。另有批量识别与保存结果重排一致、原图移动、保护输入结果目录及实时保存优先级的检查。

这些不构成真实车辆、真实路线或持续实时排名稳定性验收。本次六图只新增候选排序，没有修复此前新视频的蓝区漏检。
