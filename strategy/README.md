# 推块比赛三阶段决策

双击项目根目录 `运行策略演示.cmd`，或运行 `strategy/demo.py`，打开 **连续运行的 OpenCV 二维动画**。从 0 秒开始，小车根据当前方块位置自行选目标、接近、对准、推送和释放，时间持续推进，自动切换前中后期。无需照片、摄像头或小车。

## 动画操作

- 空格：暂停/继续。拖动方块时也会暂停计时。
- 数字 1、2、3：分别选择 1、3、6 倍速。
- R：重新开始；Esc：关闭窗口。
- 左键拖动红色方块：改变其位置。将已入区的方块拖回中线外，可以触发回收决策。
- 左键点击场地空白处：添加方块（上限 30 个）。
- 右键：放置一个对手占位障碍；O 移除。此障碍不会自主行动。

右侧显示阶段、动作执行状态、投递深度、目标区方块数和完成次数。白圈是当前目标，白线是接近路线，白色十字是推送终点。`WAIT` 表示没有可行目标，时间仍会推进。默认没有自动对手，方块推完后待命是预期行为，可手动拖回方块或添加新目标继续试验。

`demo.py` 为兼容已有命令的启动入口，`simulator.py` 实现连续演示，`planner.py` 是同一份策略核心；旧的固定时间点检查保存在 `scenario_checks.py`。

实车复用是本项目的约束：演示和实车数据接入使用同一份 `runtime.py → planner.py`，前中后期策略持续在场外电脑上运行。详见 [实车接入说明](实车接入说明.md)，其中明确了已可复用部分和仍需完成的真实执行链路。

## 已实现

| 阶段 | 默认触发条件（均需实测调整） | 行为 |
|---|---|---|
| 开局 OPENING | 前 18 秒，且尚未完成 2 次推送 | 优先正前方能被推板覆盖的一组，减少横向调整 |
| 中盘 MIDGAME | 超过开局时间、完成 2 次推送或开局被打乱 | 按收益与循环耗时选目标；可获取、回收、加深受威胁的近线方块 |
| 终盘 ENDGAME | 剩余 15 秒 | 缩短投递距离，排除来不及完成的目标及远端孤块 |
| 结束 FINISHED | 剩余 2 秒 | 停车，阶段不再退回 |

所有阶段都检查视觉/通信数据时效、急停、卡住和碰撞风险。对手正在推的方块暂不抢；根据同一方块的历史位置判断是否需要回收。目标锁定默认 0.8 秒，但危险、目标消失、收益显著下降或阶段变化可以打断。已深入目标半场的方块默认不再处理。

捕获走廊由推板宽度、两侧余量和方块半宽决定，避免按连续距离聚类得到过宽的一组。代码检查推送端点的墙边余量、直推通道内的已知对手，以及会被连带推走的非目标方块。

## 规则方向与参数

`config.json` 保存待调参数。`target_half: lower` 表示希望把方块推入坐标较小的下半场；`upper` 则相反。它表示**期望方块最终留存的半场**，不是自动假定我方半场。

计分规则尚未最终确认，因此默认 lower 只是演示方向。最近场地照片展开后蓝色在上、黄色在下，但实际摆放方向变化后不能沿用这个颜色映射。比赛时长默认 90 秒也是演示值，应按正式规则填写。

位置统一用毫米，原点在场地左下，x 向右、y 向上；车头角度从 +x 方向起算，逆时针为正，单位弧度。两轮速度、毫米与米的换算不在本模块内。

## 输入与输出

正式接入使用 `StrategyRuntime(config, started_at_s).decide(observation, feedback, now_s)`，让真实采集时间和车载心跳生成 World 中的年龄字段。模拟器也走这个入口。`Planner(config).tick(world)` 保留用于直接测试策略。一场比赛持续使用同一实例，下一场创建新实例。

- `World.robot`：机器人中心位置与朝向。
- `World.blocks`：已确认方块的位置和稳定 ID。当前照片程序的区域编号不能直接视为跨帧稳定 ID，后续需接多帧跟踪。所有年龄字段应填真实观测时效，默认 0 只方便模拟。
- `elapsed_s`：从本场启动起计算的单调递增时间。`completed_pushes` 由动作执行器在确认释放完成后累计。
- `opponent`：对手位置；`None` 只表示没有提供对手观测，不证明场地没有对手。`opponent_pushing_ids` 由视觉行为判断提供，不是本模块自动识别。
- `opening_disrupted`、`collision_risk`、`jammed`、`emergency_stop`：由比赛状态与安全监控提供。

输出 `Decision` 含阶段、动作、方块 ID、投递深度、接近点、推送终点、车头方向、估计时间及选择原因。**接近点和推送终点都是机器人中心坐标，已经考虑推板前伸距离**；不是方块目标点。

`CAPTURE` 是获取，`RECAPTURE` 是回收，`SECURE` 是加深保护。`STOP` 表示立即中止任何任务；`WAIT` 表示没有新目标，空闲执行器保持零速度。已有推送/释放任务不能仅因新目标列表为空就重启或宣布完成，而应由执行器结合最新观测、安全检查和任务进度决定继续或中止，不能盲目保留上一条速度指令。

## 当前边界

这是一版可运行的上层决策和简化运动学演示，没有向 ESP32 发送指令。动画中的位置由逐步转向、移动和接触推送计算，不按预设时间跳到指定场景。模拟接近路线采用圆形车体近似的网格搜索；未模拟推板转弯扫过范围、真实摩擦、打滑、侧向漏块或遮挡，不能据此宣称真实路径安全或预测比赛胜率。动画的任务执行器也只用于演示。

时间评分采用配置速度、转向时间、绕行系数、释放时间和预计返回时间，未从实车测量。模拟执行前会根据实际生成的接近路线再检查一次时间预算。策略到终盘会重新评估尚未完成接近的任务，正在推送时缩短投递距离；赛末停车会中断一切动作。

每个决策标记 `requires_path_check=True`：后续必须由路径规划器检查实际路线、推板转弯扫过区域、障碍物与动态对手，再复核剩余时间。当前只检查已知直推通道，不能把“生成了目标”理解为整段路径安全。对手到达时间用距离/假定速度估计，没有速度学习或落点预测。深推目前只沿纵向，不做侧角投递。

实车动作执行器后续仍需接入。演示已按“接近 → 对准 → 推送 → 释放 → 再选下一组”跟踪一次任务，推进中不会每帧重新启动接近动作。进入终盘时对活动任务的处理已提取为共享 `revise_task_for_endgame()`，实车执行器应调用同一函数。安全信号可随时中断；人工修改场地后立即放弃旧目标并重算。轮速 PID、打滑检测、视觉闭环和 ESP32 失联停车仍需实物联调，电脑端超时检查不能替代车端看门狗。

## 运行

在项目根目录的 VS Code 终端：

```powershell
.\.venv\Scripts\python.exe -X utf8 strategy\demo.py
.\.venv\Scripts\python.exe -X utf8 strategy\demo.py --target-half upper
.\.venv\Scripts\python.exe -X utf8 strategy\scenario_checks.py --json
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s strategy -p 'test_*.py' -v
```

修改配置后重新运行演示。26 项检查覆盖策略边界、连续运行和实车输入契约，包括无图形/第三方依赖运行核心、两种输入下决策一致、旧观测不被重复调用刷新、缺数据及失联停止、整场位置推进和终场停车。
